Existing approaches use generated tests as **static post-hoc validators**, which limits their effect and can mislead when the tests are wrong. **TDD-Agent** uses test-driven reasoning so tests guide implementation during repository-level code generation.

The plan stays anchored to passing tests rather than a plausible-looking diff.
