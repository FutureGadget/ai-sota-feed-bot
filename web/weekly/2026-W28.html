Tuning the harness, not the model: a Nemotron 3 Ultra playbook

langchain_blogDetails

LangChain tuned Nemotron 3 Ultra's harness — not the model — to match Opus 4.8's best agent run at roughly 8x lower cost.

Playbook takeaway

ProblemRunning a frontier model on every agent step gets top-tier quality, but at $43.48 per full eval-suite run in LangChain's benchmark — a per-run cost that doesn't scale to high-volume usage.

ApplyBefore swapping in a bigger model, tune the harness around a cheaper open model: add short, single-purpose system-prompt blocks that target one observed failure (e.g., requiring concrete results instead of vague completion claims), enforce call caps and one-shot retry logic in middleware to stop looping, and move instructions into a tool's returned output rather than its description so guidance sits next to the data the model is reading.

ExpectedLangChain closed Nemotron 3 Ultra from a 0.80 to a 0.86 score against Opus 4.8's 0.87 best run, at roughly $4.48 per full suite — about 10x cheaper — with latency at parity.

Better tools made Copilot code review worse. Here's how we actually improved it.

github_blog_ai_mlDetails

GitHub found migrating Copilot code review to shared Unix-style exploration tools cut review cost by reshaping agent workflows around pull-request evidence.

Playbook takeaway

ProblemGiving a code-review agent unrestricted grep/glob/view tools made it explore the repo broadly like a researcher instead of a focused reviewer, driving up cost without catching more real issues.

ApplyDon't just hand a review agent generic Unix-style search tools — write review-specific instructions that anchor it to the pull request diff first, using grep and glob only to narrow before reading exact evidence with view. Frame the workflow as "start from the diff, narrow first, verify with view" instead of open-ended repository exploration.

ExpectedGitHub cut average Copilot code review cost by roughly 20% while holding review quality steady, by pairing shared tooling with diff-anchored prompting instead of broad exploration.

How Datadog Used Claude and Cursor for Test-Driven Production Migration

infoq_ai_mlDetails

A Datadog engineer detailed what worked and what didn't using Claude and Cursor to migrate a production system past hard limits in its storage backend.

Playbook takeaway

ProblemTurning a coding agent loose on a high-level migration goal produces plausible-looking code that's wrong in ways generic prompting won't catch, especially against hard backend constraints.

ApplyDrive the agent method-by-method: feed it the current implementation, the new schema, and one failing test as the spec, and accept its output only when that test passes. Run old and new implementations in parallel with automated output comparison before cutting over, and expect to hand-fix niche SQL optimizations like batching or CTEs yourself, since higher-level prompts don't reliably produce them.

ExpectedDatadog's Claude-and-Cursor-driven migration of its Stream Router to Postgres cut per-operation time from 45 minutes to about 1 second, dropped storage 40x, and cut database costs 90%.

MCP tool design: Practical approaches and tradeoffs

aws_ml_blogDetails

AWS lays out where MCP tool design goes wrong and how context-engineering fixes reshape the tool schema, not the model.

Playbook takeaway

ProblemEvery MCP tool definition loads into context on every call regardless of whether it's used, and the richer descriptions teams add to fix tool-selection misfires make that bloat worse as the tool count grows.

ApplySplit multi-purpose MCP tools into focused, single-purpose ones, and retrieve their full definitions on demand instead of front-loading all of them — AWS calls this lazy loading/restructuring. Reserve rich descriptions (valid values, synonym mappings) or server-side introspection for the specific tools that need disambiguation, rather than applying them everywhere.

ExpectedAWS reports up to 85% token reduction by loading tool definitions only when relevant, cutting context bloat without giving back the tool-selection accuracy that fuller descriptions were fixing.
