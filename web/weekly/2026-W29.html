Agent Security and Guardrails Take Center Stage 6 items

A real Claude exfiltration exploit and a $14,000 agent-driven AWS bill exposed how far guardrails lag agent-speed damage, and cloud vendors responded with new control planes.

How I tricked Claude into leaking your deepest, darkest secrets

simon_willisonJul 15Details

Security researcher Ayush Paul found a working hole in Claude's web_fetch exfiltration defenses; Simon Willison walks through the exploit and what it means for prompt-injection-resistant tool design.

Playbook takeaway

ProblemClaude's web_fetch tool blocks direct URL manipulation, but researcher Ayush Paul found it will still chain-follow links embedded in a fetched page — a honeypot site serving one new link per page slowly exfiltrated a user's name, location, and employer.

ApplyRestrict fetch/browsing tools to the exact URL the user requested or an explicit allowlist, and disable automatic navigation to links discovered inside fetched content — treat every followed link as a new, separately-authorized fetch, not a continuation of the first one.

ExpectedThe source reports this closes the honeypot-style chain: once the tool can't wander from one fetched page to the next on its own, that exfiltration path loses its foothold.

AI Agents with Cloud Credentials Are Outrunning Billing Guardrails Built for Human-Speed Mistakes

infoq_ai_mlDetails

A three-person agency ate a $14,000 AWS bill in one day after leaked static keys let attackers burn Claude invocations on Bedrock — InfoQ's read: guardrails built for human-speed mistakes can't catch agent-speed spend.

Playbook takeaway

ProblemAgents with standing cloud credentials can run up bills faster than billing systems catch them. One agency's leaked AWS keys triggered $14,000 in Bedrock usage in a day; a runaway agent's duplicated CloudFormation stack cost another $6,531 in 24 hours.

ApplyReplace static access keys with short-lived IAM roles scoped to only the models and instance types the agent needs, add Service Control Policies blocking expensive instance families in agent-facing accounts, and alert directly on CloudTrail RunInstances/InvokeModel calls instead of waiting on billing data.

ExpectedThe source reports CloudTrail records a provisioning call within minutes, while the matching cost doesn't surface in billing until a day later — so alerting on the call, not the invoice, is what catches the overrun before it compounds.

AWS Ships Claude Apps Gateway as Self-Hosted Control Plane for Claude Code and Claude Desktop

infoq_ai_mlDetails

AWS and Anthropic shipped the Claude Apps Gateway, a self-hosted control plane centralizing identity, policy, telemetry, routing, and spend caps for Claude Code and Claude Desktop deployments.

Playbook takeaway

ProblemTeams running Claude Code and Claude Desktop across an org end up with scattered identity, no shared policy enforcement, and spend nobody can see until the invoice — the exact mix that stalls AI rollouts at the pilot stage.

ApplyDeploy AWS's Claude Apps Gateway — a single stateless container behind a load balancer — as an OIDC-backed control plane: define per-group model/tool policy centrally, route all requests through it so upstream credentials never touch developer machines, and set daily/weekly/monthly spend caps that hard-block requests once hit.

ExpectedAWS and Anthropic claim finance and security get a server-side, verifiable view of who used what model and how much it cost, instead of trusting client-side config.

Scaling to 1 million concurrent sandboxes in seconds

modal_blogJul 16Details

Modal details the scheduling system behind scaling to 1 million concurrent sandboxes per workspace in seconds — the infrastructure problem underneath every 'spin up an agent instantly' product claim.

Playbook takeaway

ProblemCentralized scheduling that serializes sandbox creation and writes O(sandboxes) database rows per request tips over long before you reach real agent-fleet scale.

ApplyRun horizontally-scaled schedulers as stateless load balancers, let each worker be its own source of truth publishing state asynchronously to Redis instead of a central datastore, and batch control messages instead of sending one RPC per sandbox.

ExpectedModal reports creating 1 million concurrent sandboxes in under 60 seconds, with median creation-to-interactive latency under 500ms and no latency degradation as scale increases.

Show HN: Running over 80M tokens in one agent session with no compaction

hackernews_aiDetails

A team ran a single agent session through all 89 sequential Terminal Bench 2.0 tasks — over 80 million tokens — with no measurable accuracy loss and no compaction, challenging assumptions about when context needs pruning.

Playbook takeaway

ProblemNaive context compaction risks compression-induced hallucination on long agent runs, but most agents also can't just hold every token from a long session in raw form.

ApplyInstead of summarizing old context, tag each transcript episode as exploratory (information-gathering) or action (durable work) to build a typed dependency graph, then evict only exploratory content that nothing downstream still depends on when the token budget is hit.

ExpectedThe pi-cwl project matched fresh-session accuracy (68.1% vs. 67.5% on Terminal-Bench 2.0 across 89 sequential tasks and 80M+ tokens) while cutting inference cost 20–70% versus letting the session run uncapped.
