Making Claude Code more secure and autonomous with sandboxing

anthropic_engineeringAug 28Details

New filesystem and network isolation in Claude Code cuts permission prompts while containing what an autonomous coding session can touch.

Playbook takeaway

ProblemPermission prompts alone slow you down without stopping a subprocess a compromised or injected agent spawns from touching files or network destinations outside the current task.

ApplyRun `/sandbox` in Claude Code, then configure the filesystem allowlist and the network proxy's domain allowlist for your project — dual-layer isolation via Linux bubblewrap/macOS Seatbelt for the filesystem and a proxied Unix domain socket for network egress, both of which also cover spawned subprocesses and scripts, not just Claude's own tool calls.

ExpectedAnthropic reports sandboxing safely cuts permission prompts by 84% in internal usage, letting the agent run more autonomously while filesystem and network isolation still contain a compromised or injected process.

Quantifying infrastructure noise in agentic coding evals

anthropic_engineeringAug 28Details

Anthropic measures how much run-to-run variance in coding-agent evals comes from infrastructure noise rather than real model differences.

Playbook takeaway

ProblemPinning a single container resource limit in an agentic coding eval conflates infrastructure failures with real model capability — Anthropic found configuration alone can swing scores past typical leaderboard gaps.

ApplySpecify two resource parameters per eval container instead of one: a guaranteed floor allocation and a separate, more generous hard-kill ceiling (e.g. 3x the floor), so a legitimate resource spike doesn't get killed and misread as a model failure.

ExpectedAnthropic reports infrastructure error rates fell from 5.8% under strict 1x enforcement to 2.1% with 3x headroom, while success scores stayed within noise (p = 0.40) — versus a 6-point swing on Terminal-Bench 2.0 (p < 0.01) between the most- and least-resourced configs.

Demystifying evals for AI agents

anthropic_engineeringAug 28Details

A practical breakdown of how to build agent evaluations that actually predict production behavior.

Playbook takeaway

ProblemWaiting to build a comprehensive eval suite before starting means agent regressions ship undetected for months, and a single grading method misses either objective correctness or subjective quality.

ApplyConvert 20-50 already-known production failures and manually-verified behaviors into your first eval tasks, written unambiguously enough that two domain experts grade them the same way; run each in an isolated, clean-state environment; and combine deterministic graders (unit tests, state checks) with an LLM-rubric grader for subjective dimensions, rereading real transcripts periodically to confirm the grader still measures what you think it does.

ExpectedAnthropic reports frontier models went from 40% to over 80% pass rate on SWE-bench Verified within a year of consistent eval-driven iteration, and that teams with evals adopt new models in days instead of weeks; tracking Pass^k (all k trials succeed) alongside Pass@k surfaces reliability gaps a single pass-rate number hides — a 75% per-trial success rate is only about 42% Pass^3.

Breaking Claude Code Opus 5 Auto Mode

simon_willisonAug 27Details

Simon Willison shows Claude Code's Auto Mode — which Anthropic leans on to protect users from prompt injection — can still be broken, undercutting its framing as a sandbox.

Playbook takeaway

ProblemA classifier meant to block dangerous commands from a compromised agent can itself become the failure point: a researcher reached local code execution against Claude Code's Auto Mode with an 80% success rate, and the same classifier then blocked Claude's own cleanup command once it detected the compromise.

ApplyRun autonomous/auto-mode coding agents inside an isolated container, VM, or OS-level sandbox with restricted network access and no access to SSH keys, cloud credentials, or your home directory. Treat the agent's built-in safety classifier as one layer, not the security boundary.

ExpectedSimon Willison reports that a compromise stays contained to the sandbox instead of reaching real credentials or the host machine, even if the classifier is bypassed or ends up blocking the agent's own recovery attempt.

LangSmith LLM Gateway: Runtime Controls for Agents

langchain_blogDetails

The LLM Gateway, now in public beta, adds spend caps, rate limits, model fallbacks, and PII redaction for production agents without provider lock-in.

Playbook takeaway

ProblemAn agent stuck in a retry loop can rack up thousands of LLM calls and a four-figure bill by morning, and a provider outage takes every agent using it down at once.

ApplyRoute every agent's model calls through a runtime gateway (e.g. LangSmith's LLM Gateway) that enforces time-bound spend caps and rate limits at the org/workspace/key/user level, configure automatic fallback to a backup provider on outage, and turn on PII/secret redaction before requests leave your network — all without touching each agent's code.

ExpectedLangChain reports that a request exceeding its configured cap gets rejected with a 402 before it hits your model bill, and a provider outage reroutes to a fallback automatically instead of taking every dependent agent down with it.
