AWS Open-Sources Dogwood, Extending Cedar to Govern Sequences of Agent Tool Calls

infoq_ai_mlAug 16Details

Dogwood adds temporal conditions to AWS's Cedar policy language, so rules can reason about an agent's prior tool calls — approvals, rate limits — rather than judging one request in isolation.

Playbook takeaway

ProblemA per-call approval check misses attacks and bugs that only show up across a sequence — like three separate $2,000 transfers that individually clear a $5,000 cap but together blow past it.

ApplyAdd temporal policy conditions on top of your per-call authorization: track counts, distinct values, and running sums of an agent's prior actions within a time window (AWS's open-sourced Dogwood extends Cedar with formerly, count_within, count_distinct_within, and sum_within operators for this). Sum over request events, not response events — summing responses lets concurrent in-flight calls slip past the cap before any of them return.

ExpectedAWS reports that rate limits, spend caps, and data-sensitivity rules now hold across a whole session instead of only at each isolated step.

Langfuse v4: agent evals and traces rebuilt on one immutable ClickHouse table

hackernews_aiAug 19Details

Langfuse v4 rebuilds its evals and tracing stack on a single immutable ClickHouse table.

Playbook takeaway

ProblemMutable trace/observation tables force expensive joins and deduplication at query time, so eval and cost dashboards get slower as agent trace volume grows.

ApplyAdopt an append-only, denormalized trace schema: write trace-level attributes onto each observation before ingestion instead of joining separate mutable tables at read time, so each completed observation is written exactly once (this is the architecture behind Langfuse v4).

ExpectedLangfuse reports initial large-dataset table loads dropping from seconds to milliseconds, and dashboard loads at least 10x faster on larger projects over extended time ranges.
