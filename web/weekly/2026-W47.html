Transitive Policies for Agents: Agent Permissions Don't Automatically Compose

Hacker News AIDetails

Three agents that each obey their own tool permissions can still leak customer data together, because permissions do not compose across an orchestrator.

Playbook takeaway

ProblemEach agent can obey its own tool permissions while the team still leaks private data, for example an attacker's ticket that routes a database summary to an email sender.

ApplyHave the runtime, not the model, tag content with its source and confidentiality label, and keep those labels attached across handoffs. At every outbound tool such as email or webhook, block the send unless the recipient may receive every label in the payload. Scope read tools to the requester's own records.

ExpectedCross-agent exfiltration chains fail at the send step, even when the orchestrator is fooled into making the request.

How the Claude Code team thinks about verification

Claude Dev BlogDetails

Claude writes and reviews about 90% of the Claude Code team's code, so the team relies on end-to-end, property and differential tests as agent-run verifiers.

Playbook takeaway

ProblemWithout a fast way for agents to prove their own changes work, a human must check everything, which caps you at one or two agents at a time.

ApplyAdd a `verify` skill that boots and drives the app end to end, and require it (or a code review) before each commit. Keep the gating rules on the base branch so a change can never edit the check that judges it. Run new gates in observe mode first, and escalate to a human after three failed fix rounds.

ExpectedAnthropic reports that a separate rubric grader lifted task success by up to 10 points on its structured-file tasks, and verification loops let its team run dozens of agents in parallel.
