Better tools made Copilot code review worse. Here's how we actually improved it.

github_blog_ai_mlJul 10Details

GitHub cut Copilot code review's cost by migrating it to the same Unix-style code-exploration tools human reviewers use, reshaping the agent's workflow around pull-request evidence.

Playbook takeaway

ProblemGiving a code-review agent unrestricted grep/glob/view tools made it explore the repo broadly like a researcher instead of a focused reviewer, driving up cost without catching more real issues.

ApplyDon't just hand a review agent generic Unix-style search tools — write review-specific instructions that anchor it to the pull request diff first, using grep and glob only to narrow before reading exact evidence with view. Frame the workflow as "start from the diff, narrow first, verify with view" instead of open-ended repository exploration.

ExpectedGitHub cut average Copilot code review cost by roughly 20% while holding review quality steady, by pairing shared tooling with diff-anchored prompting instead of broad exploration.

How Datadog used Claude and Cursor for test-driven production migration

infoq_ai_mlJul 10Details

A Datadog engineer detailed a test-driven production migration run with Claude and Cursor, including the storage-backend limits that AI assistance didn't remove.

Playbook takeaway

ProblemTurning a coding agent loose on a high-level migration goal produces plausible-looking code that's wrong in ways generic prompting won't catch, especially against hard backend constraints.

ApplyDrive the agent method-by-method: feed it the current implementation, the new schema, and one failing test as the spec, and accept its output only when that test passes. Run old and new implementations in parallel with automated output comparison before cutting over, and expect to hand-fix niche SQL optimizations like batching or CTEs yourself, since higher-level prompts don't reliably produce them.

ExpectedDatadog's Claude-and-Cursor-driven migration of its Stream Router to Postgres cut per-operation time from 45 minutes to about 1 second, dropped storage 40x, and cut database costs 90%.

Slack introduces agent-driven end-to-end testing

infoq_ai_mlJul 10Details

Slack's new agentic E2E testing runs workflows based on intent rather than fixed scripts, so tests adapt to UI and system changes instead of breaking on them.

Playbook takeaway

ProblemScripted end-to-end UI tests break on interface changes that have nothing to do with an actual regression, which quietly inflates maintenance load without catching more real bugs.

ApplyGive an agent a test as a goal, like "complete checkout," instead of a fixed click sequence, and let it plan, execute, observe, and try an alternate path when it hits a minor UI change instead of failing outright. Keep this pattern out of your CI blocking path for now — use it for targeted debugging and exploratory testing, and keep deterministic scripted tests as your regression gate, since agentic runs cost more per execution than a fixed script does.

ExpectedSlack's own rollout treats agent-driven E2E testing as a complement to deterministic tests, not a replacement — it's meant to cut false failures from UI churn without yet being cheap enough to run on every CI build.
