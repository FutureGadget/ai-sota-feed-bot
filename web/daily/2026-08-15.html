Cloudflare's new agent tracing adds spans for agent invocations, model calls, tool runs, and approvals to Workers traces, with turn-by-turn session replay — though the docs warn traces aren't lossless.

Playbook takeaway

ProblemAgent tracing frameworks disagree on privacy defaults: some store full messages and tool payloads unless you opt out, others store nothing until you opt in. Payloads routinely contain personal data or secrets, so the wrong default lands them in your trace store without anyone deciding that on purpose.

ApplyBefore turning on agent tracing in production, check your framework's payload default explicitly rather than assuming it matches another framework you've used. Set retention windows to match your actual debugging pattern — a 3–7 day window is short if you're chasing a pattern rather than a single incident — and budget for span volume, since every internal SDK span counts as a billed event, not just the ones you'd choose to look at.

ExpectedYou avoid the two most common tracing surprises: PII sitting in traces nobody meant to store, and an observability bill driven by spans the dashboard never surfaces.
