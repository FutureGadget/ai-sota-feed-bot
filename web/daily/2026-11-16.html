Coding agents: verification becomes the bottleneck 4 items

Teams shipping mostly agent-written code are moving trust from line-by-line human review to verification loops and run-level provenance.

How the Claude Code team thinks about verification

Claude Dev BlogDetails

Claude Code team (~90% of its code written and reviewed by Claude) explains how end-to-end, property and differential tests let agents prove their work, and how it keeps those verifiers honest.

Playbook takeaway

ProblemWithout a fast way for agents to prove their own changes work, a human must check everything, which caps you at one or two agents at a time.

ApplyAdd a `verify` skill that boots and drives the app end to end, and require it (or a code review) before each commit. Keep the gating rules on the base branch so a change can never edit the check that judges it. Run new gates in observe mode first, and escalate to a human after three failed fix rounds.

ExpectedAnthropic reports that a separate rubric grader lifted task success by up to 10 points on its structured-file tasks, and verification loops let its team run dozens of agents in parallel.
