Session Traces and Cost Controls Help Diagnose AI Agent Failures

infoq_ai_mlDetails

Session traces paired with cost controls are emerging as the standard way to spot tool-call loops and runaway spend while keeping enough context for post-incident review.

Playbook takeaway

ProblemAgent failures like tool-call loops and runaway spend are invisible in aggregate metrics, so a cost dashboard only shows the spike after the session already burned the budget.

ApplyRecord every LLM call, tool execution, and sub-agent delegation as a nested span (StackGen uses Langfuse) with latency and token cost attached, enforce hard iteration and per-tool-call caps before execution, block identical consecutive tool calls pre-execution, and flag sessions whose cost deviates from the rolling per-agent average.

ExpectedStatistical cost-anomaly checks catch model-routing errors and tool hallucinations while a session is running instead of after the invoice; keep traces for debugging and separate low-cardinality metrics for alerting, since dynamic session IDs in metric labels can crash a metrics server.
