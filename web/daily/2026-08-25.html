Introducing Rubrics: Build Agents that Evaluate and Correct Their Work

langchain_blogDetails

Deep Agents' new RubricMiddleware adds a self-eval loop: set a rubric, configure a grader, and the agent corrects its own output before returning it.

Playbook takeaway

ProblemAgent output that's close to correct still ships wrong when nothing checks it against the actual success criteria before it reaches the user.

ApplyAttach a RubricMiddleware to your agent with a grader model, a review system prompt, and any verification tools (e.g. a test runner), then pass a rubric checklist on each invocation. On failure, the grader's per-criterion feedback is injected back into the conversation and the agent retries, up to a capped number of iterations.

ExpectedLangChain reports that in their own example, a generated function which crashed on unhashable types was diagnosed by the grader and fixed on the very next iteration — targeted feedback instead of a blind retry.

LangSmith Engine Improves Agent Issue Detection by 2x

langchain_blogDetails

LangSmith Engine now detects agent issues over 2x better and proposes stronger fixes, with Slack/Linear workflows and self-hosted deployment support.

Playbook takeaway

ProblemProduction agents generate millions of traces, and manually scanning them for failure patterns and root causes doesn't scale.

ApplyPoint a trace-mining agent (e.g. LangSmith Engine) at your production trace store; it groups related failures across runs, produces evidence-backed diagnoses, drafts prompt/code fixes as ready-to-review PRs, and can keep watching a fixed issue for regressions afterward.

ExpectedLangChain reports the latest version scores over 2x better at identifying and grouping issues on its internal IssueBench and 25% better at writing correct fixes on the public Terminal-Bench, after scanning 60M+ production traces and surfacing 20,000+ issues.

Using skills with Deep Agents

langchain_blogDetails

Deep Agents CLI now discovers, loads, and executes reusable skills dynamically, cutting redundant context per run.

Playbook takeaway

ProblemLoading every tool's full definition into context upfront bloats the prompt, even though the most capable generalist agents get by on a small core tool set (Claude Code uses about a dozen, Manus fewer than 20).

ApplyStructure reusable capabilities as skill folders — a SKILL.md with YAML frontmatter — instead of hardcoded tool schemas. Load only the frontmatter by default, and have the agent read a skill's full instructions only when it determines that skill is relevant to the current task.

ExpectedBaseline context stays small no matter how many capabilities are available, since only the frontmatter for unused skills sits in context until the agent actually needs one.
