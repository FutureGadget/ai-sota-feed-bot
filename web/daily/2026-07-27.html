New Tools Aim to Catch Unsafe Agent Actions Before They Run 4 items

Belay: a local firewall for AI coding agents

hackernews_aiDetails

Belay intercepts and filters coding-agent actions locally, before they reach the file system or shell.

Playbook takeaway

ProblemA coding agent with shell or MCP access can be steered into destructive commands, secret exfiltration, or supply-chain attacks faster than a human reviewer can catch it in the diff.

ApplyAdd a local, rule-based interceptor (e.g. Belay) between the agent and its tool calls that denies irreversible commands (rm -rf, shell injection, secret file reads) outright, routes ambiguous ones to a human Ask step with a timeout-deny default, and hash-verifies skill files so an approved skill can't be swapped afterward.

ExpectedBelay reports deciding in under 100ms with no LLM or cloud round-trip in the decision path, blocking destructive, exfiltration, and supply-chain attack classes before they execute; the project frames this as defense-in-depth, not a guarantee against obfuscated payloads.

EvoCode-Bench tests agents across 227 sequential rounds

philschmidDetails

Single-turn benchmark scores overstate reliability; the real failure mode is regressions across a persistent workspace, not missing features.

Playbook takeaway

ProblemSingle-turn benchmarks overstate how reliable a coding agent is — in EvoCode-Bench's multi-round runs, top agents fail mostly by breaking earlier working code, not by failing to add new features.

ApplyBuild a multi-round eval harness that reuses one persistent workspace across sequential tasks, with a cumulative test suite that re-checks every prior requirement after each new change, and require the agent to maintain a running requirements document it consults before editing.

ExpectedIn EvoCode-Bench, agents that kept a persistent requirements document more than doubled their success rate, and the gap between single-turn and multi-turn scores (up to 4x on lower-tier models) narrows.

AWS pitches task-aware knowledge compression as RAG's next step

aws_ml_blogDetails

Traditional RAG breaks down on analytical tasks spanning hundreds of documents; AWS's TAKC pre-compresses knowledge bases into task-specific representations instead.

Playbook takeaway

ProblemSimilarity-search RAG surfaces relevant chunks but misses the cross-document connections analytical questions spanning hundreds of documents need.

ApplyOffline, chunk documents and compress them at multiple ratios (e.g. 8x/16x/32x/64x) using task-aware prompts that preserve what that task cares about — revenue figures for financial analysis, violations for compliance — then route each incoming query to the lightest compression tier that still answers it: heavy compression for simple lookups, light compression for complex analysis.

ExpectedAWS reports token cost dropping from about 10% of full-context cost with top-10-chunk RAG to about 6.25% at medium (16x) compression and about 1.6% at ultra (64x) compression, while preserving cross-document connections RAG misses.
