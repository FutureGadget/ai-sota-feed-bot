AWS Ships Claude Apps Gateway as Self-Hosted Control Plane for Claude Code and Claude Desktop

infoq_ai_mlDetails

A self-hosted control plane that centralizes identity, policy, telemetry, routing, and spend caps for Claude Code and Claude Desktop, letting enterprises run their own governance layer instead of trusting a hosted one.

Playbook takeaway

ProblemTeams running Claude Code and Claude Desktop across an org end up with scattered identity, no shared policy enforcement, and spend nobody can see until the invoice — the exact mix that stalls AI rollouts at the pilot stage.

ApplyDeploy AWS's Claude Apps Gateway — a single stateless container behind a load balancer — as an OIDC-backed control plane: define per-group model/tool policy centrally, route all requests through it so upstream credentials never touch developer machines, and set daily/weekly/monthly spend caps that hard-block requests once hit.

ExpectedAWS and Anthropic claim finance and security get a server-side, verifiable view of who used what model and how much it cost, instead of trusting client-side config.

Agents need their own computer. Here's how to give them one safely.

langchain_blogDetails

Argues agents need disposable, isolated execution environments rather than shared dev boxes, since letting an autonomous agent run in a shared container risks state leaking between tasks.

Playbook takeaway

ProblemAgent-written code often executes before a human reviews it, and a shared container can't fully isolate that risk from your other work.

ApplyRun each agent task in its own hardware-virtualized microVM with an independent kernel and filesystem, inject credentials via proxy instead of baking them into the image, and use snapshot-and-fork so parallel fix attempts branch from one base image without sharing state.

ExpectedLangChain reports that what runs in one microVM can't affect what runs in another, so a broken or compromised agent run stays contained to itself.

Presentation: Postgres for Production Agents: Your Relational Foundation for Enterprise AI

infoq_ai_mlDetails

Gwen Shapira details how teams scale AI features on PostgreSQL using JSONB parsing and high-recall HNSW vector indexes instead of standing up a separate vector database.

Playbook takeaway

ProblemA separate vector database adds a second system to operate, and it still can't give an agent deterministic relational context alongside semantic search.

ApplyUse Postgres's own JSONB indexing for semi-structured payloads, an HNSW index (not IVFFLAT) for embeddings, and quantize vectors from 32-bit floats to 8- or 16-bit; give agents high-level DB tools plus row-level access control instead of raw SQL.

ExpectedOne system covers both deterministic relational queries and semantic retrieval, and the source reports quantization alone delivers a 4x improvement in memory, disk, and CPU cost.
