# v2.1 Execution Plan — Storyline Signal Density & Recall Hygiene

## Problem
Investigation of the live storyline pipeline (21-day window, 2026-06-19) found the
reader-facing value is bottlenecked **upstream** of the editor agent, not in
narration. The narrative layer (`storyline-editor`) is strong; the weak links are
node compression, candidate redundancy, and a floor that discards verified links.

Guiding principle (decided in design review): **do not chase raw recall.** Naively
widening the funnel (higher caps / lower floor) floods agent context with
surface-similar near-duplicates, degrading judgment. Optimize **signal density**
(distinct threads per token the agent reads), not article count.

## Diagnosis (evidence)
- **Node-dedup is effectively inert.** `dedup_nodes` only merges *verbatim-identical*
  significant-title signatures. Over the live window: **474 records → 473 nodes**
  (1 merge, junk), **0 nodes span >1 source**. The Claude Fable launch is present as
  two separate nodes (latent.space AINews vs Anthropic newsroom) — same event, not
  collapsed. Same-event re-syndications leak through uncompressed.
- **Candidate fragmentation.** One real cluster spawns many overlapping anchor-pair
  candidate rows (the NVIDIA launch → 5 of 15 near-miss slots). The cap then drops on
  this inflated set; the agent reads N views of one story.
- **Floor discards verified links.** Of 3 high-confidence scout links, only 1 surfaces.
  `nvidia-nemotron-3-ultra` (judge-confirmed, 2 sources / 2 days) is blocked solely by
  `MIN_ITEMS 2<3`. A scout link's precision is supplied by the judge, so the item-count
  noise-guard double-charges it.
- **Trust hygiene leaks.** Index card label "Fable Mythos" vs editorial "Claude Fable"
  (anchor-pair label ≠ narrative label); orphan duplicate permalink
  `claude-fable-2026-06-09.json` (narrative-less slug-fork of the live `claude-fable`).

## Goals
1. Compress same-*event* re-syndications into one node before any agent reads them.
2. De-fragment the scout candidate set so each slot is a distinct thread.
3. Recover judge-verified links without enlarging agent context.
4. Close the label/permalink trust leaks.

## Phases (priority order — signal density first)

### Phase 1 — Stop the dedup leak  (`pipeline/build_storylines.py::dedup_nodes`) — DONE 2026-06-20
- Added a third merge pass: fold a pair when the smaller significant-title set is
  ~contained in the larger (`NODE_CONTAIN_MIN = 0.8`), from distinct sources within
  `NODE_MERGE_DAY_GAP = 2` days, sharing a distinctive (non-`WEAK`) token. Candidate
  pairs gathered via distinctive-token buckets.
- Over-merge guard is the **containment metric itself**: a storyline beat adds new
  facts and falls below 0.8; calibration against the live window confirmed every
  `cont=0.67` pair is a genuinely different beat (launch vs hands-on vs suspension)
  that stays split. See ADR 2026-06-20.
- Result on live window: multi-source nodes 0 → 2 (Fable launch + suspension each
  collapse), no false merges; `claude-fable` 7 → 6 nodes covering one more article.

### Phase 2 — De-fragment candidates  (`pipeline/scout_candidates.py`) — DONE 2026-06-20
- Before `MAX_NEAR_MISS`, union near-miss rows whose node-sets overlap `>= MERGE_OVERLAP`
  (the cluster-merge bar reused from `build_storylines`) into one candidate; merged rows
  carry an `anchors[]` provenance list. Rows sharing only one common node (overlap below
  the bar) stay separate — Nemotron release→availability vs RTX/LoL correctly split.
- Effect on live window: near-miss dropped 26 → 11; the 15 shown slots are now 15
  *distinct* threads (the NVIDIA roundup no longer occupies 5 of them), so genuinely
  distinct candidates previously crowded out now reach the agent. No cap raise.

### Phase 3 — Recall-safe floor for confirmed links  (`pipeline/build_storylines.py::cluster`) — DONE 2026-06-20
- Scout links now gate on `SCOUT_MIN_ITEMS = 2` (vs `MIN_ITEMS = 3` for anchor pairs)
  while `MIN_DAYS`/`MIN_SOURCES` are unchanged — the judge supplies the precision, so
  the item-count noise-guard double-charges a verified link. Anchor-pair floor untouched.
- Live window: `nvidia-nemotron-3-ultra` (2 items / 2 days / 2 sources) surfaces
  `via_scout`; single-source `xiaomi-mimo-code` stays inert. Post-judge stage — adds
  zero articles to agent context.

### Phase 4 — Trust hygiene
- **Label reconciliation:** make the index/card label agree with the editorial label
  (prefer narrative-supplied canonical label, else reconcile `cluster_label` with slug).
- **Orphan/duplicate slugs:** detect a detail file that is a stale slug-fork of a
  carried-over slug and emit a redirect/canonical pointer so the old permalink resolves
  to the live thread instead of a narrative-less duplicate.

### Deferred — Phase 5 (separate plan): evidence-bound synthesis threads
Cross-surface "bigger picture" threads connecting articles with no shared vocabulary.
High value, high trust-risk; needs its own design (evidence-bound + distinctly labeled).
Explicitly out of scope here — to be revisited *after* Phases 1–2, since synthesis over a
deduped, high-signal node set is the whole point.

## Validation
- Re-run `dedup_nodes` over the live window: multi-source node count rises from 0;
  same-event pairs (Fable launch, Nemotron) collapse; topic-only pairs stay split.
- `scout_candidates.py`: NVIDIA no longer occupies multiple near-miss slots.
- `build_storylines.py`: `nvidia-nemotron-3-ultra` surfaces (`via_scout`); `xiaomi`
  still does not. No spurious new storylines vs. current index.
- Manual: `/storyline/claude-fable` card label matches editorial; old
  `claude-fable-2026-06-09` permalink redirects to `claude-fable`.
- Run `skills/ai-feed-digest-local/scripts/run_dev.sh` end-to-end; no regressions.

## Rollback
Each phase is independent and revertible in isolation. Phases 1–3 are localized to
`dedup_nodes` / `scout_candidates.main` / the `c["scout"]` branch of `cluster()`; revert
restores prior behavior and the next pipeline run regenerates clean `data/storylines/`.
Phase 4 label/redirect changes are additive metadata.
