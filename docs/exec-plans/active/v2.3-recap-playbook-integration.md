# v2.3 Execution Plan — Action-mapped recaps with Playbook integration

## Status

Implemented 2026-06-22.

Implemented defaults: weekly cap 5, daily cap 3; weekly input includes
news/release/research/paper; vendor/project numbers carry a visible
`Source claim` label; the inline primary action opens a related topic page when
available and otherwise opens the canonical Playbook edition.

## Problem

Daily and weekly recaps explain what happened, while `/playbook` separately
explains what an agent/platform engineer should change. Readers must make that
connection themselves. The highest-value recaps should bridge the two without
turning every news item into forced or generic advice.

The desired experience is an optional inline **Playbook takeaway** beneath a
recap article:

```text
Problem  High cold-start latency when restoring agent state.
Apply    Serialize execution state into graph capsules and load it on demand.
Result   Lower restore latency; show a number only when the source supports it.
```

## Outcome

- A strong, source-backed Playbook card appears inline beside the matching
  article in weekly and daily recaps.
- The Playbook agent remains the only editorial author of
  `problem → apply → result`.
- Recap agents summarize and organize news; they do not independently rewrite
  Playbook advice.
- Matching, eligibility, caps, validation, and rendering are deterministic.
- `/playbook` remains the canonical action archive.

## Success criteria

- Every embedded takeaway resolves to exactly one canonical Playbook card and
  one original source article.
- No quantitative result is displayed without explicit evidence metadata.
- Recaps with no matching cards render exactly as they do today.
- Weekly recaps can include high-value releases, research, and papers when they
  produce an actionable card; daily recaps remain tighter and primarily
  news-oriented.
- The regular agent routine produces Playbook cards before the recap routine
  that consumes them.
- A reader can scan the recap without the inline cards making it materially
  longer: target cap is 5 weekly and 3 daily takeaways.

## Non-goals

- Generate a takeaway for every recap article.
- Re-enable an LLM inside the deterministic hourly pipeline.
- Let recap agents create a second, divergent version of a Playbook card.
- Personalize action cards per reader.
- Embed evergreen wiki advice into a recap unless it is tied to the exact
  source article being summarized.
- Backfill old recaps with inferred or invented source provenance.

## Architecture decisions

### 1. Playbook editions are canonical

The agent-written file under `data/playbook/<date>.json` owns the editorial
content. Recaps receive a deterministic read-only overlay. They do not copy or
persist a second authored `problem/apply/result` object.

### 2. Match by stable source identity, not title

Each source-backed card carries:

```json
{
  "id": "pb-<stable-id>",
  "kind": "source-backed",
  "source_url": "https://original.example/article",
  "source_sid": "sha256(source_url)[:16]",
  "topic_url": "/topic/context-compaction",
  "problem": "...",
  "apply": "...",
  "result": "...",
  "evidence": {
    "kind": "source-measured",
    "note": "The paper reports a 70% reduction in its tested setup."
  }
}
```

- `source_url` is copied verbatim from the Playbook input bundle.
- `source_sid` uses the repository's existing story-permalink identity.
- `topic_url` is optional and links to the durable wiki explanation.
- `url` remains a compatibility field during migration, then is deprecated.
- Title matching is never used.

### 3. Distinguish source-backed from evergreen cards

The existing June 21 Playbook edition points at `/topic/...` pages and does not
identify the source articles from which its advice was derived. Those cards are
valid evergreen Playbook content, but they are not eligible for recap embedding.

Card kinds:

- `source-backed`: eligible for recap embedding; requires `source_url`,
  `source_sid`, and evidence metadata.
- `evergreen`: valid on `/playbook`; may use `topic_url`; never joined to a
  recap article.

No source URL will be guessed while migrating existing cards.

### 4. Evidence is explicit

`evidence.kind` is one of:

- `source-measured` — the primary source reports the stated number.
- `source-claimed` — a vendor/project claims the result, but it is not an
  independent measurement.
- `editorial-inference` — the result is a reasonable expected outcome, stated
  qualitatively.

Rules:

- A numeric `result` requires `source-measured` or `source-claimed`.
- `source-claimed` results must be worded as claims, not established facts.
- `editorial-inference` results cannot contain unsupported percentages,
  multipliers, benchmark scores, or absolute guarantees.

### 5. Generate one deterministic source index

`build_playbook_index.py` also writes:

`data/playbook/source-index.json`

The index maps `source_sid` to the latest valid source-backed card. It contains
only fields needed by recap rendering plus the canonical edition/card
references. Duplicate cards for the same source are a validation error unless
an explicit supersession rule is later added.

Both the Python static renderer and the browser recap shells consume this same
artifact. Recap JSON files remain unchanged and backward-compatible.

### 6. Deliver weekly first

The weekly recap is the first vertical slice because it has room for durable
research/release takeaways and is the clearest test of the product hypothesis.
Daily integration reuses the same contract and renderer after weekly is proven.

Weekly input changes from news-only to all engineering-relevant types
(`news`, `release`, `research`, `paper`), while the agent remains responsible
for hard curation. Daily remains news-first; a source-backed Playbook match does
not automatically force an article into the daily recap.

### 7. Agent routine ordering

The recurring editorial sequence becomes:

```text
build Playbook input
    → Playbook agent writes source-backed cards
    → validate + build source-index
    → build recap input
    → recap agent writes recap
    → validate + render recap with deterministic card overlay
```

The Playbook skill performs the semantic work. The recap skills only receive
and display validated matches.

## Reader experience

- Inline block label: `Playbook takeaway`.
- Hierarchy: `Apply` is visually dominant; `Problem` and `Expected` are quieter.
- The block links to the canonical `/playbook?date=<date>` edition and, when
  available, the related `/topic/<slug>` page.
- The article title continues to link to the original source.
- Takeaways are omitted entirely when no source-backed match exists.
- Rendering caps:
  - Weekly: at most 5, selected in recap article order.
  - Daily: at most 3, selected in recap article order.
- One card per article and one appearance per recap.
- Mobile rendering stays single-column and preserves the recap's finish line.

## Dependency graph

```text
Playbook card contract + evidence rules
    → Playbook validator
        → source-index.json
            → weekly input coverage
            → weekly static + dynamic rendering
                → daily rendering reuse
                    → routine scheduling + measurement
```

## Test matrix

| Case | Expected behavior |
|---|---|
| Exact source URL/SID match | Inline card renders |
| Same/similar title, different URL | No card |
| Evergreen `/topic/...` card | Visible on `/playbook`, absent from recap |
| Numeric result + measured evidence | Number renders with measured label |
| Numeric result + vendor claim | Claim wording and claimed label render |
| Numeric result + inference | Validation fails |
| Qualitative inferred result | Card may render |
| Duplicate source-backed cards | Index build fails |
| More than weekly/daily cap | Earliest recap-order matches render; rest logged |
| Missing/corrupt source index | Recap renders without cards |
| Unsafe HTML in card text | Escaped on static and dynamic surfaces |
| Old recap with no matching card | Existing appearance preserved |

## Rollout

1. Land schema/index changes with no recap UI enabled.
2. Produce at least one real source-backed Playbook edition and inspect the
   source index.
3. Enable weekly rendering behind a configuration flag or constant defaulting
   off in production previews.
4. Review a Vercel preview using a representative weekly recap.
5. Enable weekly in production and observe one publication cycle.
6. Enable daily after the weekly checkpoint.
7. Remove the temporary flag only after both surfaces prove stable.

## Metrics

Primary:

- Click-through rate from an inline takeaway to its source, Playbook edition,
  or topic page.
- Percentage of weekly recaps with at least one validated takeaway.
- Save/share behavior on recap pages containing takeaways versus those without.

Guardrails:

- Median number of inline cards per recap.
- Percentage of candidate cards rejected by evidence validation.
- Recap completion/scroll-to-finish rate; it should not fall materially.
- Zero unsupported numeric-result incidents.

Initial evaluation window: four weekly editions and fourteen daily editions.
Do not tune ranking or source selection based on this feature until that window
has enough observations.

## Risks and mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Generic advice is forced onto weak articles | High trust loss | Source-backed cards are optional; Playbook agent curates hard |
| Vendor benchmark claims look like facts | High | Required evidence kind and claim-aware wording |
| Existing evergreen cards are incorrectly matched | High | Separate card kinds; no guessed provenance |
| Recaps become too long | Medium | Hard caps, compact design, daily remains news-first |
| Playbook runs after recap publication | Medium | Explicit routine ordering; no-match degrades cleanly |
| Same source gets conflicting cards | Medium | Duplicate-source validation failure |
| Static and dynamic pages diverge | Medium | Shared generated source index plus parity tests |
| Adding papers/releases lowers weekly signal | Medium | Input broadens, publication does not; agent still curates |
| URL normalization causes false joins | Medium | Use copied source URL plus repository-standard SID; no title fallback |

## Rollback

- Disable inline rendering; recap JSON and archive files remain unchanged.
- Keep `source-index.json` as an unused additive artifact or stop generating it.
- Revert weekly input defaults to news-only.
- Source-backed Playbook cards continue to work on `/playbook`; no editorial
  data is lost.
